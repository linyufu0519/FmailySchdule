【USER 需求】
  在當日行程列表與行程詳細畫面加入「加入手機行事曆」功能，將目前查看的單次
  行程匯出為標準 .ics。重複行程只匯出當次 occurrence，不輸出整個系列。

--------------------------------------------------------------------------------

【影響範圍】

  程式位置一：js/ics-export.js
  函式／區塊：buildIcsContent
  說明：產生單次 occurrence 的 iCalendar 內容。
  異動：新增 VCALENDAR／VEVENT 必要欄位、floating local time、成員說明、
        ICS 特殊字元跳脫、跨日結束日期與單次 UID。保留既有已驗證的 CRLF、
        escape、重複單次與跨日計算。

  修改前：
    無此功能。

  修改後：
    export function buildIcsContent(event, occurrenceDateKey)
    export function buildIcsFilename(event, occurrenceDateKey)

  ─────────────────────────────────────────────────────────────────────────────

  程式位置二：js/calendar-export.js、js/app.js
  函式／區塊：openCalendarExport、exportEventToCalendar
  說明：Storage HTTPS 匯出的瀏覽器互動流程。
  異動：click handler 立即設定按鈕 loading（顯示「正在準備…」），非同步上傳
        ICS 至 Storage。成功後在**目前分頁**用 windowObject.location.assign()
        導向 getDownloadURL，不開新分頁；失敗時停留原頁、解除 loading、記錄
        console.error 並顯示錯誤 toast。使用者完成或取消行事曆匯入後可用瀏覽器
        返回鍵回到家庭行事曆頁面。

  ─────────────────────────────────────────────────────────────────────────────

  程式位置三：js/cloud-sync.js
  函式／區塊：Storage SDK 初始化、uploadCalendarFile
  說明：上傳 ICS 並取得 HTTPS 下載 URL。
  異動：新增 Firebase Storage 10.12.2 CDN module；路徑只含 familyId、UUID 與
        固定安全檔名。Blob/metadata MIME 固定 text/calendar，Content-Disposition
        使用 ASCII event.ics，customMetadata 僅記錄 createdAt。

  ─────────────────────────────────────────────────────────────────────────────

  程式位置四：tests/calendar-storage.test.js、tests/calendar-export.test.js
  說明：Storage 安全路徑、metadata 與同頁導向流程測試。
  異動：驗證路徑不含標題/成員、UUID 唯一、familyId、MIME、metadata，以及
        成功時於目前頁面 location.assign 導向下載網址、失敗時不導向並回報
        onError、loading 狀態正確恢復。已移除舊版 placeholder/popup 相關測試。

  ─────────────────────────────────────────────────────────────────────────────

  程式位置五：index.html、README.md、FIREBASE_SETUP.md
  說明：移除 Shortcuts UI 並記錄 Storage 隱私與清理方式。
  異動：刪除首次設定按鈕/Modal/教學；說明 HTTPS 實體檔較可靠但 iOS 行為仍依
        版本而異。明確揭露長效 token 風險，提供手動刪除與 age=1 day Lifecycle 建議，
        不宣稱前端會自動清理。

--------------------------------------------------------------------------------

【未修改項目】
  Firestore 行程資料模型
  說明：匯出資料由既有 event 與 occurrenceDateKey 即時計算，不需新增欄位或遷移資料。

  重複行程儲存規則
  說明：ICS 不輸出 RRULE，刻意只產生當下點選的單一 VEVENT，符合單次匯出需求。

  Storage 自動清理
  說明：前端離頁後無法保證延遲刪除，故未實作不可靠的自動清理。需由管理者手動
        刪除或在 Google Cloud Storage 設定 Lifecycle Policy。

--------------------------------------------------------------------------------

【測試建議】
  1. 一般行程從當日列表下載 .ics，確認標題、時間與成員正確。
  2. 從詳細 Modal 下載相同行程，確認內容一致。
  3. 點選重複行程第二次 occurrence，確認 ICS 日期為當次日期且沒有 RRULE。
  4. 使用含逗號、分號、反斜線與換行的標題，確認匯入後文字完整。
  5. iPhone Safari 點擊後確認按鈕立即顯示「正在準備…」，完成後於目前分頁
     導向 HTTPS .ics，可用返回鍵回到家庭行事曆。
  6. 模擬 Storage 上傳失敗，確認停留原頁、顯示明確錯誤 toast 並解除 loading。
  7. 定期檢查 calendar-exports 檔案清理或 Lifecycle Policy 是否生效。
